# Методика отклика HTTPS и оптимизация 1.1.0

## Что измеряет приложение

Миллисекунды — время успешной попытки после DNS до HTTP-заголовков: новое TCP-соединение, TLS и ожидание сервера. Это не ICMP-пинг. DNS разрешается отдельно на каждой попытке и остаётся внутри общего пользовательского тайм-аута; его время сохраняется отдельно. Повторы неудачной попытки не складываются с длительностью успешной.

Медиана берётся по успешным адресам сервиса. Среднее медиан выбранных сервисов преобразуется в `clamp((1000 − мс) / 90, 0, 10)`. Доступность X/Y остаётся отдельной оценкой. TLS, IPv4, HTTP/1.1, отдельные удерживаемые сокеты, запрет proxy/редиректов и число проверок сохранены. Сайт Twitch использует GET до заголовков; остальные адреса — HEAD.

## Изменения без сокращения проверки

- Один общий снимок и тестовый процесс на стратегию для всего выбранного набора. Для 22 стратегий — 22 снимка, 22 запуска `winws` и 22 коротких экспорта фильтра. Ранее три сервиса требовали 44 тестовых процесса и 44 экспорта из-за отдельного LoL-варианта.
- Четыре процесса по умолчанию, до двух запросов внутри процесса; допускается 1–8 процессов. Повторы одного адреса последовательны; endpoints сервисов чередуются. Сохранённая пользовательская параллельность не изменяется.
- Общие ресурсы хешируются один раз за проход обнаружения. Ключ — полный путь, сравнивается содержимое. Открытые файловые дескрипторы запрещают запись и удаление до конца прохода. Между проходами кеш не сохраняется; проверка целостности защищённых снимков остаётся.
- Промежуточные результаты пишет один последовательный обработчик, объединяя частые обновления с интервалом до секунды. Сериализация вынесена из блокировки состояния. Финальная публикация и подтверждение результата происходят вместе после повторной проверки отмены; поздняя старая запись не может заменить окончательную.
- Обычные IPC-обновления ограничены четырьмя в секунду и одной последней ожидающей сводкой. Начало, завершение, ошибки и ответы команд приоритетны. Запоздалые ревизии отбрасываются и сервером, и GUI.
- Выбранный набор образует самостоятельный вариант. Его результаты связываются с одной завершённой серией; старые отдельные проверки не выдаются за подтверждение общей стратегии.

## Измеренный этап подготовки

16 октября 2026 года на локальной Flowseal 1.10.3 выполнены четыре одинаковых прохода 22 профилей. Сравнивались прямое повторное хеширование и общий контекст прохода. Каждый раз отпечатки совпали побайтно; общий контекст прочитал 22 уникальных ресурса.

| Проход | Без общего контекста, мс | С общим контекстом, мс |
|---|---:|---:|
| 1 | 194,35 | 20,71 |
| 2 | 192,61 | 24,17 |
| 3 | 180,34 | 18,67 |
| 4 | 160,04 | 18,75 |
| Медиана | 186,47 | 19,73 |

Это примерно 167 мс экономии только на хешировании. Данные не означают ускорения всей сетевой серии в такое же число раз. Проходы выполнялись в одном процессе, порядок был «без контекста → с контекстом»; файловый кеш ОС мог влиять на значения.

## Живая приёмка ещё не завершена

Системный запрос UAC был отменён. Даже `winws --wf-save` требует повышения через манифест бинарника; статический экспорт нового общего варианта без UAC не состоялся. Поэтому для этой рабочей сборки не заявляются ни подтверждённая живая изоляция нового пути, ни полное время серии, ни ускорение сетевых проверок.

Подготовлены отдельные приёмочные сценарии: прежняя очередь трёх сервисов на четырёх процессах, новая общая очередь с теми же тремя сервисами и затем шестью, отмена при подготовке/запросах/финальном сохранении, конфликт WinDivert, падение общего процесса, сбой сохранения, откат профиля и портового пула, нативный отрицательный контроль.

Сравнение проводится при одинаковых четырёх процессах, двух попытках и пяти секундах. Сохраняются время серии, этапы discovery/snapshot/export/readiness/network/save/cleanup, число запусков, пики процессов/запросов, фактические IP, HTTP-коды и ошибки. Суммарные времена параллельных этапов перекрываются и не равны времени серии. Разница вариантов адаптации также должна учитываться при интерпретации сетевого результата.

Настройки тайм-аутов остаются у пользователя. До приёмки установленная копия и стабильный выпуск GitHub не заменяются.
